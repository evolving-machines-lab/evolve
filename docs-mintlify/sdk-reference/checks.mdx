`checks()` returns the checks client.

## create

<Tabs>
  <Tab title="TypeScript">
    ```ts
    create(input: { source: { directory: string } | { dataset: string }; model_name?: string; rubric?: Rubric; prompt?: string; reasoning_effort?: string; sandbox_provider?: EvalSandboxProvider; n_concurrent?: number; include_task_names?: string[]; exclude_task_names?: string[]; n_tasks?: number; onUploadProgress?: (sentBytes: number, totalBytes: number) => void }): Promise<Check>
    ```

    Check a local task directory, or a directory of them (packed and streamed as one archive; `upload_too_large` past what the store or the spool disk can hold), or a published dataset (nothing uploaded; the version resolves as for a job, `dataset_not_found`, `no_active_version` or `version_not_ready`, and a version whose package was not retained is `invalid_input`). Returns the accepted check, one `queued` result per task; an empty selection is refused with `no_checkable_tasks`. The check's `source` records which form ran. A check on a dataset version also appears on every job spanning it, as `check` on `jobs().tasks()` rows.

    ```ts
    const check = await checks().create({ source: { dataset: "my-swe@1.0" } });
    ```
  </Tab>
  <Tab title="Python">
    ```python
    async def create(
        directory: Optional[str] = None,
        *,
        dataset: Optional[str] = None,
        model_name=None,
        rubric: Optional[Rubric] = None,
        prompt=None,
        reasoning_effort=None,
        sandbox_provider=None,
        n_concurrent=None,
        include_task_names=None,
        exclude_task_names=None,
        n_tasks=None,

    ```

    Check a local task directory, or a directory of them (packed and streamed as one archive; `upload_too_large` past what the store or the spool disk can hold), or a published dataset (nothing uploaded; the version resolves as for a job). One source, not both. Returns the accepted check, one `queued` result per task; an empty selection is refused with `no_checkable_tasks`. A check on a dataset version also appears on every job spanning it, as `check` on `jobs().tasks()` rows.

    ```python
    check = await checks().create(dataset="my-swe@1.0")
    ```

## task, transcript, artifact

<Tabs>
  <Tab title="TypeScript">
    ```ts
    task(taskCheckId: string): Promise<TaskCheck>
    transcript(
      taskCheckId: string,
      options?: { since?: number },
    ): Promise<TaskCheckTranscript>
    artifact(
      taskCheckId: string,
      stream: "trace-stdout" | "trace-stderr",
    ): Promise<string | null>
    artifact(
      taskCheckId: string,
      stream: "agent-home",
    ): Promise<Record<string, string> | null>
    ```

    One task's result by its task check id, the checker's own transcript (everything after `since` in one read, `total` counting all stored rows), or one stored artifact. A task check stores no verifier log and no ATIF trajectory, so those selectors are refused; an id of another kind of run is refused naming its kind. An id you may not read answers `trial_not_found`.

    ```ts
    const result = await checks().task(done.results[0].id);
    ```
  </Tab>
  <Tab title="Python">
    The Python client has no per-task reads. A task's result is in `Check.results`, returned by `get` and `watch`.
  </Tab>
</Tabs>

## download

<Tabs>
  <Tab title="TypeScript">
    ```ts
    download(id: string): Promise<Buffer>
    download(
      id: string,
      options: { to: string },
    ): Promise<string>
    download(
      id: string,
      options: { stream: true },
    ): Promise<ReadableStream<Uint8Array>>
    ```

    The whole check by its check id (`check-<id>/` with `check_report.json` and one folder per task), or one task's folder by its task check id (`check-<task>__<7 chars>/`), as one `.tar.gz`, verified as a job download is. Each task folder holds `config.json`, `lock.json`, `result.json`, `trial.log`, `exception.txt` on an infrastructure failure, `agent/claude-code.txt`, `agent/stderr.log`, `agent/trace-parsed.jsonl`, the home with `agent/agent-home.json`, `verifier/test-stdout.txt`, `reward.txt` and `reward.json` when the validator ruled (1 for a valid result, 0 when refused), and `artifacts/manifest.json` with `artifacts/check-result.json` on a completed run. An id that is neither answers `check_not_found`; an unsettled check or task check answers `check_not_terminal`.

    ```ts
    const path = await checks().download(
      check.id,
      { to: "./checks" },
    );
    ```
  </Tab>
  <Tab title="Python">
    ```python
    async def download(

    ```

    The whole check by its check id (`check-<id>/` with `check_report.json` and one folder per task), or one task's folder by its task check id (`check-<task>__<7 chars>/`), as one `.tar.gz`, verified as a job download is. An id that is neither answers `check_not_found`; an unsettled check or task check answers `check_not_terminal`.

