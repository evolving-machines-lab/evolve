---
title: "Secrets"
description: "Store secrets once, attach by name."
---

An env secret is a value stored under a name, with a delivery mode. Values are write-only: every read returns metadata, never the value.

```bash
printf %s "$GITHUB_TOKEN" | evolve secrets set GITHUB_TOKEN --delivery brokered \
  --allowed-host api.github.com --allowed-path-prefix / --allowed-method GET
```

Pipe the value on stdin, as above, to keep it out of your shell history. `--value <value>` is the other channel. `--delivery` is required: `brokered` means the value never enters the sandbox and needs the `--allowed-*` scoping; `direct` places the raw value in the sandbox environment and refuses scoping. `--label <label>` keeps several values of one name side by side; the default label is `default`.

Restating the same value re-shapes its delivery or scoping. A different value under an existing name and label is refused: delete it first, or use another label.

```bash
evolve secrets list
evolve secrets delete GITHUB_TOKEN --label staging
```

## Attach a secret to a job

```bash
evolve run -d terminal-bench-4@4.0 -a codex -m gpt-5.5 --secret GITHUB_TOKEN --watch
```

`--secret NAME[@LABEL][=ENVNAME]` attaches a stored secret to every agent run. `@LABEL` picks a labeled row; omitted, the `default` row, or the only row. `=ENVNAME` renames the variable inside the sandbox. The job stores a reference, and the value never rides the command line.

`--secret-inline NAME[@LABEL]:DELIVERY=VALUE` saves the value and attaches it in one step. Re-running the same command with the same value converges; a different value under the same name and label is refused.

Plain, non-secret environment goes on `--ae KEY=VALUE`.

Every flag is in the [secrets reference](/cli-reference/secrets).
