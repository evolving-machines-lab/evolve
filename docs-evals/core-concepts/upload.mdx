---
title: "Upload a job"
description: "Bring a job you ran elsewhere onto the platform: a Harbor job folder, or Evolve SDK runs packed as one."
---

A job you ran elsewhere uploads as a finished job. Its trials, traces and rewards become a job you read, analyze and share like any other.

```bash
evolve upload ./job-2026-08-27__12-00-00 -d terminal-bench-4@4.0
```

`upload` takes the job folder, or its `.tar.gz`. With `--from <url>` it takes a public https URL of the archive instead. `-d name[@version]` links the trials to a published dataset version by task name. The command follows the import until the job exists; `--no-wait` returns at once with the import id.

```bash
evolve job imports --status RUNNING
evolve job import <import-id> --watch
```

## What a job folder holds

The Harbor job layout, exactly what `evolve job download` and `harbor job download` produce:

```text
job/
├── config.json                   the job record
├── result.json
└── <trial>/                      one folder per trial
    ├── result.json               REQUIRED — the trial's facts (below)
    ├── agent/
    │   ├── trajectory.json       the trace, in Harbor's trajectory format
    │   ├── stdout.log            the harness's output (any agent/*.txt or *.log also counts)
    │   └── …                     the agent's home, stored byte for byte
    ├── verifier/                 test-stdout.txt, reward.txt
    ├── artifacts/                the agent's deliverables
    ├── steps/                    multi-step trials, as Harbor writes them
    └── trial.log, exception.txt
```

Every file but `result.json` is optional. What is absent stays absent: a trial without a trace shows no trace, a trial without a home shows no files.

## What `result.json` must hold

```json
{
  "task_name": "my-task",
  "trial_name": "my-task__deepseek",
  "trial_uri": "",
  "task_id": {},
  "task_checksum": "",
  "config": {},
  "agent_info": { "name": "codex", "version": "0.154.0", "model_info": { "name": "deepseek-v4.1-flash" } },
  "verifier_result": { "rewards": { "reward": 1.0 } },
  "exception_info": null,
  "agent_execution": { "started_at": "2026-09-16T18:08:27Z", "finished_at": "2026-09-16T18:08:38Z" }
}
```

The first seven keys are required. `verifier_result.rewards` is the score: names to numbers, `reward` the primary. Harbor's exception names (`ScoringError`, `InfrastructureError`, `ApiUsageLimitError`, `CancelledError`) map to their statuses; any other name stays as written. `agent_result` carries tokens and cost when you have them.

## Runs made with the Evolve SDK

Every SDK run is logged to a local file under `~/.evolve-sdk/observability/sessions/`. Its header line names the agent and model, and its raw lines are the transcript. To bring such runs onto the platform, pack one trial folder per run: the header's agent and model into `agent_info`, the raw lines at the harness's own transcript path under `agent/` (for codex `agent/.codex/sessions/<yyyy>/<mm>/<dd>/rollout-<id>.jsonl`, for claude `agent/.claude/projects/<project>/<session>.jsonl`), and the score, when you have one, in `verifier_result.rewards`. Raw transcripts anywhere else under `agent/` are stored as files but not read as the trace.

## What lands

- Rewards → `SCORED`, rewards untouched.
- No rewards → no score. Not an error.
- `exception_info` → the exception, kept as written.
- Trace, logs, home, verifier log, artifacts, steps → where a native trial's are.
- A prior `analysis.json` → not imported. Analyses run here.

The job carries `upload`: the archive's `original_job_id` and `original_job_name`, `uploaded_at`, the uploader's `reported_totals`, `task_links`. Resume, retry and regrade refuse an uploaded job (`job_uploaded`); analyze works on it. The CLI prints `ported` as the provider, and after the import `scored N of M trial(s)`. Zero of many is a warning: check `verifier_result.rewards`.

## Task linkage

Each trial's `lock.json` names its task by content hash; a task the platform holds with the same hash links by itself. A linked trial's analyses run with the task folder, an unlinked trial's without it, and the record says why: `hash_mismatch`, `task_not_in_dataset`, `no_task_digest`, `no_hash_match`, `no_dataset_named`, `dataset_ambiguous`. A name alone never links.

`-d name@version` overrides: it links by task name to that version and settles an ambiguous hash.

## Bounds and duplicates

- One limit: the archive ceiling `limits.uploads.job_archive_bytes` (`upload_too_large`).
- A trial with a file over 5 GiB, or a trajectory too large to parse, is skipped (`trial_too_large`); the rest lands.
- A `result.json` that cannot be read fails the import (`invalid_trial`).
- The same job twice: `job_already_uploaded`. Delete it, then upload again.
